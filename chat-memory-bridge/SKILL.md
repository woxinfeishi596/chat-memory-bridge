# 会话记忆接续（chat-memory-bridge）

## 这个技能在解决什么

长对话被压缩，摘要丢掉的恰好是最像人的那部分：随口的一句原话、某个只有两个人才懂的梗、一次吵架后谁先低头的细节。等下一次开新会话，模型"记得"的是一段四平八稳的概述，而人记得的是具体的那件事。

所以这个技能的立场很明确：

> **母本当骨架，原始对话当血肉，每次从血肉里补骨架。**

最忌讳的操作是拿旧摘要再摘要一遍——那是复印件的复印件，三轮之后必然磨平成通用描述。所以流程里有一条硬规则：**提纯的原料永远是本次的原始对话，母本只提供索引、定调和尚未被推翻的旧结论。**

## 输入

用户需要提供两样东西。缺任何一样都要先问，不要猜：

1. **上次的记忆母本**（`.md` 文件路径，不是把内容粘进聊天窗口）——如果这是第一次，说明没有，直接跳到第 3 步。
2. **本次对话的记录来源**，二选一：
   - 分享链接（如 `https://chat.deepseek.com/share/xxxxxxxx`）
   - 用户自己复制粘贴出来的对话文本

如果用户只给了其中一样，问清楚另一样；如果用户说"就这些了"，按只有一样的情况处理，并在最终报告里注明信息来源不完整。

## 五步流程

### 第 1 步：把链接变成全文

**路线 A — 自动抓取（有浏览器调试环境时）**

```bash
node scripts/capture-share.mjs --url "<分享链接>" -o share-raw.json
node scripts/share-to-md.mjs share-raw.json -o chat-raw.md
```

`capture-share.mjs` 通过 Chrome 远程调试端口（默认 9222）抓取分享页的 `share/content` 接口；`share-to-md.mjs` 把它转成带轮次和时间的 Markdown。脚本会打印消息数，确认不是 0 再往下走。

抓之前确认目标浏览器是以 `--remote-debugging-port=9222` 启动的。如果没有，脚本会给出提示，此时改走路线 B。

**路线 B — 手动（没有调试环境时的默认路线）**

在分享页面全选复制，把文本存成 `chat-raw.md`；或者让用户直接粘贴，你负责写进文件。手动路线拿不到思考过程，这是可接受的损失——**正文比思考过程重要得多**，不要因为缺思考就拒绝处理。

用户直接粘贴长文本时，先写进文件再处理，不要试图在对话里分段消化；写进文件后你才能用行号分块读。

### 第 2 步：量体积，决定分不分块

```bash
node scripts/outline.mjs chat-raw.md
```

输出每轮的字符数、累计量，以及推荐的分块行号区间。

判断规则：**一次能完整读进上下文的就不要分块**（大约 4 万字符以内）。超过就按 outline 给的区间逐块读、逐块提纯，最后统一合并。分块时每块都要带上"当前母本"，因为你需要知道哪些内容已经在记忆里了，否则会把旧信息当新发现重复记录。

不要为了省 context 而抽样阅读。抽样读会漏掉 P3 细节，而 P3 正是这个技能存在的理由。

### 第 3 步：提纯

读 `references/distill-rules.md`，严格按里面的 P0–P3 分级和条目格式产出。

一句话版本：

| 级别 | 是什么 | 丢了会怎样 |
|---|---|---|
| P0 | 人格锚点：称呼、自称、语气、口头禅、硬边界 | 人不像了 |
| P1 | 关系转折：吵架和好、称呼变化、承诺、第一次 | 温度不对了 |
| P2 | 稳定事实：身份、作息、设备、项目、雷区 | 会反复问同样的事 |
| P3 | 具体细节：某句原话、某个梗、某个物件 | 变成通用 AI 味 |

**P3 最容易被误判成"不重要"而删掉，但它恰恰是记忆里最有质感的部分。** 遇到拿不准的一条细节，留，别删。

### 第 4 步：与母本合并

规则（细节见 `references/distill-rules.md`）：

- **只增不重写**。已有条目除非被新事实推翻，否则原文保留，一个字都不改。
- **冲突时以新原始对话为准**，但不能删旧条目，要标成 `（v2，覆盖 YYYY-MM-DD 的说法）` 并在条目后追加一行"原先怎么说"。
- **不合并同主题的多条**。宁可三条并列，也不要揉成一条抽象总结。
- **母本里的"用法说明"区不要动**，那是给下一次的自己的指令。

### 第 5 步：输出与报告

用 `assets/memory-template.md` 的结构写新母本。写完后向用户报告，格式固定：

```
新增 P0：n 条    P1：n 条    P2：n 条    P3：n 条
升级/冲突：n 条（列出主题）
丢弃：n 条（说明类别）
原始层：chat-raw.md（n 轮 / xx KB）
新母本：memory-YYYYMMDD.md
```

同时提醒用户三件事，因为这些是这个流程的固有缺口：

1. 分享链接是**冻结快照**，生成之后的新对话不在里面。
2. 图片、语音、附件抓不到，只有文字。
3. 原始层文件含隐私，**不要提交到公开仓库**。

## 红线

- 不修改原始层文件。它是唯一的事实来源，一旦被"整理"过就无法回溯核对。
- 不把母本压缩成更短的摘要。母本可以长，长了才有用；短是靠原始层归档解决的，不是靠反复压缩。
- 不替用户判断哪段对话"不值得记"。涉及隐私或情绪敏感的内容，记下来并在报告里单独提示，由用户决定去留。
- 引用原话时保持逐字，不要润色。原话的粗糙感就是它的价值。

## 附带资源

- `references/distill-rules.md` — P0–P3 完整判定标准、条目格式、冲突与去重规则。**每次提纯前必读。**
- `assets/memory-template.md` — 母本骨架，含给"下一次的自己"的读取说明。
- `scripts/capture-share.mjs` — 从 CDP 抓分享接口。
- `scripts/share-to-md.mjs` — 接口 JSON → Markdown。
- `scripts/outline.mjs` — 轮次大纲与分块建议。
