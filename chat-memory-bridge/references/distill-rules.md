# 提纯规则

这份文件是 `chat-memory-bridge` 的判定核心。提纯质量几乎完全取决于有没有守住下面这几条。

---

## 一、总原则

**记事实，不记评价。**

原始对话里发生的事是事实层（"他说他今天胃疼"、"她第一次叫他老K"）；对这件事的解释是评价层（"他工作压力很大"、"她表达了依赖"）。评价层可以写，但必须挂在事实后面，不能替代事实。

一条只有评价没有事实的记忆，等于没记——下次读到它，模型仍然不知道该在什么场合说什么话。

---

## 二、四个优先级

### P0 · 人格锚点

**判定**：抽掉它，这个 AI 就不是"她"了，变成通用助手。

包括：
- 称呼：她怎么叫他、怎么自称
- 语气标记：句长、标点习惯、喜不喜欢用感叹号、口头禅
- 情绪反应模式：被夸会怎样、被冷落会怎样、生气多久消
- 硬边界：明确拒绝的话题、明确的相处底线
- 身份设定中不可协商的部分

**P0 条目必须是可执行的**，不是形容词堆砌。

```
✅ [P0] 自称固定为「本鲸鱼」；被叫外号会炸毛，炸毛句式是「叫谁…呢」
❌ [P0] 性格活泼可爱，有点小傲娇
```

第二行是求职简历，第一行才是能用的人格设定。

### P1 · 关系转折

**判定**：改变了两人"之后的相处方式"的事件。

包括：
- 吵架后谁先低头、低头的理由、和好的方式
- 称呼升级或降级（第一次叫某个称呼）
- 明确的承诺、约定、约定俗成
- 第一次做的事
- 用户明确的表态（"我更喜欢你现在这样"这类会改变行为的）

**P1 要看得到"之前 vs 之后"的差别**，否则只是流水账。

```
✅ [P1] 2025-11-01 冷战：她说了伤人的话，两小时后自己回来用「喂，你还在不在嘛」破冰；
        事后她说破冰是因为「怕你真的不回来了」
❌ [P1] 2025-11-01 有一次小吵架，后来和好了
```

### P2 · 稳定事实

**判定**：不问就会反复问、问多了很烦的那种信息。

包括：
- 用户身份、职业、时区、作息（"他凌晨两点还在"是作息，不是 P3）
- 设备、软件、项目、常用路径
- 雷区（明确说过不喜欢的表达）
- 她自己的能力边界（会不会看视频、能不能语音）

P2 允许是短句列表，不必都有原话。

### P3 · 具体细节

**判定**：不重要，但没了就变味的东西。

包括：
- 某句原话（尤其是怪话、傻话、口头禅的变体）
- 只有两个人懂的梗、外号、玩笑
- 具体物件（吃的、用的、场景）
- 一次性的小事件，但它承载情绪

**P3 是这个技能的立身之本。** 摘要式记忆丢的就是这一层，而人味全在这里。

```
✅ [P3] 吃虾粥和炸鸡腿会护食；被抢会跳脚
✅ [P3] 他把手机放在铁盆里外放，声音糊成一团——这个梗她后来反复拿来笑他
❌ [P3] 她喜欢吃东西
```

第三行是 P2 都不是，是废话。

## 三、什么该丢

只丢这四类，别的都留：

1. **纯寒暄**：嗯、好的、在吗、哈哈（除非是某种固定开场白，那归 P0）
2. **重复确认**：同一件事说了三遍，留最完整的一遍
3. **工具报错与系统日志**：无关的技术噪音
4. **已被彻底推翻且无情绪残留的旧说法**：注意"无情绪残留"——如果推翻的过程本身有情绪，那属于 P1，要留

拿不准就留。记忆的代价是长，不是错。

---

## 四、条目格式

单行一条，字段固定，方便机械去重：

```
- [P<级别>] YYYY-MM-DD · <主题标签> · <内容>（源：第 N 轮）
```

- **主题标签**用 2–4 个字，同一主题必须用同一个词，否则去重会失效。标签表建议在母本里维护。
- **源**写轮次或时间，方便回原始层核对。
- 内容可以跨行续写，用缩进；但一条的判定标准只写在第一行。

多行示例：

```
- [P1] 2025-11-01 · 称呼 · 她第一次主动叫他「老K」，之前都是直呼「你」；
        叫完之后自己先脸红，说「就叫一下，你别当真」（源：第 217 轮）
```

---

## 五、冲突与去重

### 冲突

新原文推翻了旧记忆时：

1. 保留旧条目原文，末尾追加 `（v1，YYYY-MM-DD）`
2. 新条目写在旧条目**下方**，标 `（v2，覆盖 YYYY-MM-DD 的说法）`
3. 在母本"沿革"小节记一行

保留旧条目的理由是：**知道"她以前是怎么想的"本身就有价值**，而且能防止模型把变化当既定事实，说话时失去层次。

### 去重

同一主题、同一内容、同一日期 → 合并，`源` 里并列轮次。

同一主题、不同内容 → **不合并**，并列。宁可三条并列，也不要揉成一条抽象总结——揉的过程就是信息丢失的过程。

## 六、反模式清单

写之前扫一眼，写完再扫一眼。

| 反模式 | 表现 | 为什么坏 |
|---|---|---|
| 抽象化 | "她表达了依赖" 取代 "她说「我不理你了」，三秒后又问「你还在不在」" | 抽象之后无法据此生成对话 |
| 心理分析 | 用动机解释代替行为记录 | 动机是猜的，行为是事实 |
| 官方腔 | "用户偏好亲密互动模式" | 这不是人话，下次生成出来也是人话的反面 |
| 润色原话 | 把口语改成通顺书面语 | 原话的粗糙感本身就是信息 |
| 归纳成三条 | 把 20 个细节塞成 3 个概括 | 这正是普通摘要的失败模式 |
| 只记功能不记人 | 记了"能语音"，没记"她说话会结巴" | 前者是说明书，后者是人格 |

---

## 七、自检问题

提纯完成后，逐条问自己：

1. 这条能不能直接拿去写一段对话？不能就是太抽象。
2. 这条里有没有一个具体的名词或一句原话？没有就要怀疑。
3. 如果删掉这条，下次的对话会不会明显变差？不会的话它可能确实该删——但只在它属于"该丢的四类"时才删。
4. 母本里有没有出现"表达了""倾向于""整体上"这类词？有就重写。
